# 音频配置与排障

[返回产品首页](../README.md) · [CLI / API](AUDIO_API.md)

## 配置从哪里来

从仓库根目录运行 `audio-*` 命令时，会读取当前目录的 `.env` 中允许的音频/SSL 字段。`audio-demo` 始终离线，忽略这些真实服务配置。已有进程环境变量优先于 `.env`；修改文件不会更新已运行的服务。

macOS 的 `start.command` 会先进入仓库目录，在缺少 Mureka Key 时提示输入并保存，随后在 8767 启动。直接调用 `audio-serve` 不会询问 Key。音频服务默认端口统一为 8767；启动脚本也支持 `--port` 与 `--audio-dir`。端口占用时提供原服务地址和重启指引，不自动结束其他进程。

原生 MIDI Planner 的环境变量属于另一条实验路径，不由音频 `.env` 加载器处理，见 [原生 MIDI 文档](NATIVE_MIDI.md)。

## 主要配置

下表描述**当前代码的约束**，不承诺供应商未来的模型权限或计费方式。

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `BEATMATE_AUDIO_PROVIDER` | `mock` | `mock` 离线测试；`mureka` 真实服务 |
| `BEATMATE_AUDIO_LIVE` | 未启用 | 真实服务必须显式设为 `1` |
| `MUREKA_API_KEY` | 空 | 自己的 Mureka API Key；由后端使用 |
| `MUREKA_MODEL` | 空 | 真实模式必须明确指定；当前接受 `mureka-7.6`、`mureka-8`、`mureka-9`、`mureka-9.5`，不接受 `auto` |
| `MUREKA_BASE_URL` | `https://api.mureka.ai` | 当前仅支持这个国际服务入口 |
| `BEATMATE_AUDIO_MAX_CANDIDATES` | `1` | 本地允许请求的候选数上限，当前为 1 或 2；只有 1 时页面显示文字提示 |
| `BEATMATE_AUDIO_MAX_SUBMISSIONS` | `1` | 未保存页面设置时使用的累计调用上限，支持正整数 |
| `MUREKA_DOWNLOAD_HOSTS` | `cdn.mureka.ai` | 逗号分隔的精确可信下载域名；不接受通配符或内网目标 |
| `SSL_CERT_FILE` / `SSL_CERT_DIR` | Python 环境默认 | 可选可信 CA 文件或目录；不会关闭证书校验 |

完整无秘密模板见 [`.env.example`](../.env.example)。不要通过改目录或重建数据库绕过本地调用记录。

## 输入与输出

| 输入 | 当前限制 |
| --- | --- |
| 音乐名 | 可选，最多 50 字符；不写进音乐描述 |
| 纯伴奏音乐描述 | 必填，与显式制作偏好合计最多 1024 字符 |
| 歌词歌曲的歌词 | 必填，1–5000 字符；独立提交 |
| 歌词歌曲的制作要求 | 可选，与显式制作偏好合计最多 1024 字符 |

预览显示实际将提交的描述及歌词。超长内容会报错，不静默截断。BPM/情绪等文字是请求值，实际音频不保证严格遵循。

原始音频优先保存 WAV，其他格式据实保留；不把解码校验产物替换成交付文件。歌曲分离返回伴奏、人声 ZIP；同次响应存在 MIDI 地址时，再保存 MIDI ZIP 和包内文件。MIDI 下载不再次调用付费分离。

## 调用额度不等于余额

设置 → 调用额度中的上限保存到当前音频目录的 SQLite，立即生效，并优先于环境变量。它是本地防止失控提交的计数，不能当作实际费用预测：

- 纯伴奏每次请求预留 1 次调用。
- 歌词歌曲预留 `1 + 候选数` 次调用，包含后续分离。
- 失败和结果不确定的请求仍占预留；删除与重启不会归零。
- Mock 不占真实调用额度；修改上限本身不会发起生成。

在同一数据目录可用 CLI 查看或保存：

```bash
.venv/bin/python -m beatmate audio-budget
.venv/bin/python -m beatmate audio-budget --limit 100
```

## 运行与连接检查

在设置中打开「运行检查」，查看配置、解码器、可信证书、运行版本、音乐库和配置文件位置。代码或 `.env` 改变后会提示重启；这里不会返回 Key 的值。

也可从仓库根目录执行：

```bash
.venv/bin/python -m beatmate audio-doctor
.venv/bin/python -m beatmate audio-doctor --network
```

第一条只检查本地环境；第二条在 Mureka 模式检查官方 API 域名的 DNS、TCP 和 TLS，握手后立即断开，不发送 HTTP 或 Authorization，不创建任务、不扣费。Mock 模式直接跳过网络。连接成功不代表账户、模型权限、余额或下载域名正常。

## 常见问题

| 现象 | 含义与处理 |
| --- | --- |
| 新按钮没有出现或提示服务版本过旧 | 只刷新了页面，旧 Python 服务仍在运行。在原终端 `Ctrl+C`，重新启动，再刷新；不要额外启动第二个同端口服务 |
| `MUREKA_API_KEY missing` / 模型未配置 | 检查启动目录、`.env` 和已有环境变量；在 macOS 用 `./start.command` 输入 Key |
| 本地调用额度不足 | 在页面设置中保存新累计上限；歌曲需要同时预留分离调用 |
| 生成请求尚未发送 | 生成提交前连接失败。新记录区分 DNS、TCP、TLS；检查网络和可信 CA 后，由用户决定是否重新创作 |
| 原任务查询或下载失败 | 已有生成任务，继续恢复原任务；不要仅因临时连接错误再生成 |
| 提交结果不确定 | 无法确认供应商是否接收，不自动重发；先核对供应商账户。移入回收站只隐藏记录，不改变事实状态 |
| TLS 证书校验失败 | 配置该环境的可信 CA。macOS 可检查 `/etc/ssl/cert.pem` 是否适用，再写入 `.env` 的 `SSL_CERT_FILE`；保持校验开启 |
| 浏览器能联网，但 Python 连接失败 | 当前音频传输直接建立连接，不读取浏览器代理配置；检查 Python 所在网络环境。不要通过禁用 TLS 处理 |
| 有整曲，没有分轨或 MIDI | 展开作品查看分离与下载状态。未返回 MIDI 或旧记录未保存下载地址时，不能凭空补出 MIDI，也不会自动再付费分离 |
| 音频只有 4 秒 | Mock 的固定测试信号。检查页面服务标识及 Provider 配置 |
| MIDI 与 WAV 听感差别很大 | MIDI 是音符转录，不包含原录音音色和混音，需要在 DAW 选择乐器并校正 |
| 音频一直等待保存 | 检查下载域名、网络、文件校验和解码器。非 PCM 格式需 `ffmpeg` 或 macOS `afconvert` |

使用多个目录时，CLI 与网页必须指向同一个 `--audio-dir` 才能看到相同任务与设置。备份整个目录前先停止服务；不要只复制数据库而丢掉音频文件。
