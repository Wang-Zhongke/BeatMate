# 音频架构演进

这是历史设计摘要。当前操作与接口以 [产品首页](../../README.md)、[Audio API](../AUDIO_API.md) 和 [配置指南](../CONFIGURATION.md) 为准。

## 从原生 MIDI 到音频工作台

早期实验使用结构化规格驱动规则引擎，生成 MIDI 和参考 WAV。音频工作台另建独立 SQLite 库，通过供应商生成与分离接口取得实际音频；两条路径保留各自数据模型，互不迁移快照。

## 保留的工程约束

- 请求先持久化，再调用外部服务；请求 ID 与内容绑定。
- 有供应商任务 ID 时恢复查询与下载，提交结果不确定时不自动重发。
- 原始任务与产物记录不可变；歌名、收藏、备注及回收站状态独立保存。
- HTTPS、公网下载域名限制、大小与格式校验，以及 SHA-256 文件完整性检查。
- 分离和 MIDI 产物各自记录保存进度，已有整曲不因分离未完成而消失。
- Mock 为离线工程测试信号，真实生成需显式开启。

## 已退出当前界面的设计

早期 Direct / Template 双模式和歌词自动摘要入口已移除。当前界面直接保留描述原文，并区分纯伴奏与歌词歌曲；部分旧 CLI/API 参数保留用于历史兼容，不代表新的推荐创作方式。

原生 MIDI schema 1 见 [早期规格](DESIGN.md)，schema 2 见 [Creative V2](CREATIVE_V2.md)。
